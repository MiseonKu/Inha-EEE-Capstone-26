# P1 Lessons Applied To P2

- Need an end-to-end package, not only FK/URDF.
- Geometry authority must be fixed first.
- FK check script must exist.
- Target, schedule, and trajectory generation must be separate.
- Target count must be CLI-controllable.
- Trajectory must include smooth return-to-basic.
- Metadata must include geometry and label policy.
- `verification_report_p2.md` is required.
- Heavy ROS2/Gazebo workflows are avoided for Windows preparation.
- Matplotlib is the standard validation method.
- Vive comparison scaffold must exist from the start.
- Dataset files must preserve q, `target_id`, `trial_id`, and geometry metadata.

The P1/06 materials are reference patterns only. They are not treated as complete or authoritative for P2.
